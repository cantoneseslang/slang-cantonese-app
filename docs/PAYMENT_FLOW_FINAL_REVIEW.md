# 決済フロー最終レビュー

## 現在の実装

### 1. 既存サブスクリプションがある場合
- **同じプラン**: `alreadyActive: true`を返す ✅
- **異なるプラン**: Checkout Sessionを作成して決済画面にリダイレクト ✅
- **問題**: 新しいCheckout Sessionを作成すると、2つのサブスクリプションが存在する可能性がある

### 2. Checkout Session作成
- 既存の顧客IDを使用 ✅
- メタデータにuser_idとplanを設定 ✅
- 決済完了後にWebhookで会員種別を更新 ✅

### 3. Webhook処理
- `checkout.session.completed`: 新規サブスクリプションの場合、会員種別を更新 ✅
- `customer.subscription.updated`: 既存サブスクリプション更新の場合、会員種別を更新 ✅
- **追加**: 既存サブスクリプションをキャンセルする処理を追加 ✅

## 残存する問題

### 問題1: 2つのサブスクリプションが存在する可能性
- **原因**: 既存サブスクリプションがある場合、新しいCheckout Sessionを作成すると、新しいサブスクリプションが作成される
- **影響**: ユーザーが2回請求される可能性がある
- **修正**: Webhookで既存サブスクリプションをキャンセルする処理を追加済み ✅

### 問題2: 決済が確実に完了するかどうか
- **現在**: Checkout Sessionを作成して決済画面にリダイレクト
- **問題**: ユーザーが決済をキャンセルした場合、会員種別は更新されない ✅（これは正しい動作）

### 問題3: 有効期限の計算
- **現在**: 固定の日付を使用（1ヶ月後、1年後）
- **問題**: サブスクリプションの実際の期間終了日を使用していない
- **修正**: Webhookでサブスクリプションの`current_period_end`を使用 ✅

## 推奨される追加修正

1. **有効期限の計算を修正**: サブスクリプションの`current_period_end`を使用
2. **決済確認の強化**: 決済が完了するまで会員種別を更新しない（既に実装済み）
3. **エラーハンドリングの強化**: 決済が失敗した場合の処理を追加
